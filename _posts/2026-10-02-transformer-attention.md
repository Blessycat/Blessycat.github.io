先修要求：矩阵乘法、softmax 和基本 PyTorch 张量操作。本文聚焦解码器式语言模型中的自注意力，代码使用已有的 PyTorch CPU 环境即可。

注意力最容易被抽象名词遮住。可以先把它理解为一条具体计算规则：当前位置生成一个查询，用它给可见位置打分，把分数归一化为权重，再对那些位置的内容做加权求和。难点不在这个比喻，而在分数如何产生、哪些位置允许参与，以及实际需要储存多大的中间张量。

## Q、K、V 是同一输入的三种投影

设一条序列有 T 个 token，隐藏维度为 d。输入 X 的形状是 `[T,d]`。三个可训练投影分别生成查询 Q、键 K、值 V。单头情形下，Q 和 K 的最后一维为 d_k，V 的最后一维可取 d_v。于是 `Q @ K.T` 的形状是 `[T,T]`：第 i 行第 j 列，表示第 i 个位置给第 j 个位置的兼容性分数。

标准缩放点积注意力写成：

$$
Y=\operatorname{softmax}\left(\frac{QK^{\mathsf T}}{\sqrt{d_k}}+M\right)V.
$$

softmax 沿键的位置维度计算，所以每个查询位置的权重总和为 1。输出仍有 T 行，内容维度变成 d_v。Transformer 原论文给出了这一构造和多头注意力设计。[Attention Is All You Need](https://arxiv.org/abs/1706.03762)

为什么除以根号 d_k？在简化假设下，若 q、k 的各维独立、均值为零且方差为一，点积中 d_k 个乘积项相加，方差约为 d_k。维度变大时分数分布变宽，softmax 更容易饱和。缩放将分数尺度控制在相近范围。这是用于理解的统计推导，不意味着训练中的各维始终独立或严格服从某个分布。

## 用三个位置算一次加权平均

假设某个查询得到的三个缩放后分数是 `[0, log(2), 0]`，指数化后为 `[1,2,1]`，归一化得到 `[0.25,0.5,0.25]`。如果三个值向量只有一维，分别为 `[2,10,6]`，输出就是 7。

这个数不是模型选择了第二个位置，而是三个位置都贡献了信息。注意力权重也不能直接等同于“这句话对最终答案的因果贡献”：后续还有值投影、输出投影、残差和其他层。理解计算机制与解释整个模型行为，是不同层次的问题。

多头注意力把投影分为 h 组，让各组在自己的子空间里计算。常见形状是 `[B,h,T,d_head]`，其中 `d=h*d_head`。每头输出拼接后，再经输出投影回到模型维度。增加头数不等于凭空增加同等倍数的隐藏宽度；如果 d 固定，每头维度会相应变小。

## 因果掩码约束的是信息，而不是标签

自回归训练中，第 i 个位置用于预测下一个 token，只能看到当前位置及之前的位置。因果掩码把未来位置的分数置为负无穷；softmax 后，这些位置权重为零。若忘记掩码，模型在训练时能看到答案，loss 可能漂亮地下降，生成时却无法复现这种条件。

下面是一个为了观察中间矩阵而写的直接实现，适合很短的教学序列：

```python
import math
import torch

torch.manual_seed(7)
q = torch.randn(1, 2, 4, 3)
k = torch.randn(1, 2, 4, 3)
v = torch.randn(1, 2, 4, 3)
scores = q @ k.transpose(-2, -1) / math.sqrt(3)
allowed = torch.ones(4, 4, dtype=torch.bool).tril()
weights = scores.masked_fill(~allowed, float("-inf")).softmax(-1)
out = weights @ v
assert out.shape == (1, 2, 4, 3)
assert torch.allclose(weights.sum(-1), torch.ones(1, 2, 4))
assert torch.all(weights.masked_select(~allowed) == 0)
```

真实模型通常调用融合实现。PyTorch 的 scaled dot product attention 支持因果模式，但布尔 mask 中 True 表示允许参与；这与部分其他 API 的掩码语义相反。还应注意该函数的 dropout 由 `dropout_p` 控制，评估时需要传入 0。[PyTorch SDPA](https://docs.pytorch.org/docs/main/generated/torch.nn.functional.scaled_dot_product_attention.html)

padding mask 与 causal mask 也不能混为一谈。前者描述哪些位置只是补齐，后者描述时间方向。SFT 中的 loss mask 则描述哪些预测参与监督；不计算用户 token 的损失，并不意味着模型不能读取用户输入。

## 注意力为什么让长上下文变贵

显式注意力分数含 B×h×T×T 个元素。取 B=1、h=16、T=4096、每元素 2 字节，仅一个分数张量就需要 536,870,912 字节，即 512 MiB。T 增加到 8192 后，这一项变为 2 GiB。这里尚未加入 softmax 输出、其他激活、梯度或权重，因此不能把该数字当成整层显存。

计算量同样包含随 T 平方增长的注意力部分。但线性投影和前馈网络也有成本，通常包含 T×d² 项；短序列或宽模型下，不能一看到 Transformer 就断言所有时间都花在注意力矩阵上。

FlashAttention 的重要思想是按块计算并减少高带宽显存与片上存储间的数据搬运，从而避免完整物化某些大中间矩阵。它是精确注意力的高效实现，不是把全连接注意力改成近似稀疏注意力，也不会自动消除所有二次计算。[FlashAttention 原论文](https://arxiv.org/abs/2205.14135)

因此，“优化后显存接近随序列长度线性增长”和“算法的所有计算都已变成线性”是两件事。用具体的实现、形状、dtype 和硬件解释测量，比只引用复杂度符号更有帮助。

## 一个 Transformer 块还剩什么

注意力之外，残差连接让子层学习对已有表示的修正；归一化控制数值尺度；前馈网络对每个位置做非线性变换。位置编码或旋转位置编码提供顺序信息。仅有无位置信息的自注意力，不能自行知道两个输入 token 的先后关系。

训练通常一次处理整段序列，利用因果掩码并行计算所有位置。逐 token 生成则可缓存历史 K、V，避免为相同前缀反复计算投影。KV cache 是推理状态；它与训练为反向传播保存的激活不是同一个对象，不能把推理缓存的公式直接当成训练显存公式。

## 用缓存形状区分训练与生成

对于标准多头注意力，若有 L 层，缓存长度为 T，KV 头数为 h_kv，每头维度为 d_head，单个元素占 b 字节，则仅 K、V 缓存的理想大小为 `2*L*B*T*h_kv*d_head*b`。例如 12 层、批次 1、长度 1024、8 个 KV 头、每头 64 维、每元素 2 字节，缓存合计约 24 MiB；这仍不含权重、激活、管理结构或预留容量。

一些架构让多个查询头共享较少的 KV 头，因此不能总用查询头数替代 KV 头数。读取模型配置时，应同时检查两者。一次生成新 token 时，查询长度可以是 1，而键长度已经是整个历史长度，此时注意力分数形状不再是方阵。

这也使掩码对齐更容易出错：方形训练掩码中熟悉的下三角，在带缓存的非方形输入中未必表达想要的绝对位置关系。调用底层 API 前要确认其因果对齐语义，不能仅把训练代码的布尔开关原样移过去。高层生成接口通常处理这些状态，手写实现时则要把缓存位置和可见区间一起验收。

## 主机实验与验收

先运行短序列实现，打印第一头的权重矩阵。第一行应只有第一个位置能参与，最后一行才能访问四个位置。随后只修改最后一个 token 对应的 K、V，比较前三个位置的输出：在正确因果掩码下，它们应保持不变。这个干预比观察矩阵是不是三角形更直接地验证了信息隔离。

再将手写实现与 SDPA 在 `dropout_p=0`、相同输入和因果设置下比较，使用合理浮点容差。最后用纸笔计算 T 从 128 到 256、512 时显式分数矩阵的元素数，不需要真的分配超大张量。

验收是能解释每个维度、指出未来信息泄漏在哪里发生，并区分数学注意力、内核实现和完整模型三种成本。本文提供的是教学实验设计，未报告任何 GPU 吞吐或显存实测值。
