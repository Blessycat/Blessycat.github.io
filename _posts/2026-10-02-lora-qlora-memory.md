“只训练百分之一参数”并不意味着“只用百分之一显存”。训练仍需读取底座权重、保存必要激活，并计算梯度传播。理解 LoRA 与 QLoRA，最有帮助的方式是把显存账本拆开：哪些张量不再需要梯度，哪些权重被压缩，哪些成本仍然存在。

## 低秩更新改变的是参数化方式

设线性层底座权重 W 的形状为 `[d_out,d_in]`，LoRA 将可训练增量写成两个小矩阵的乘积：

$$
W'=W+sBA,\qquad
A\in\mathbb{R}^{r\times d_{in}},\quad
B\in\mathbb{R}^{d_{out}\times r}.
$$

底座 W 冻结，A、B 可训练，原始常见缩放为 `s=alpha/r`。相应前向是 `Wx+sB(Ax)`，不必先构造完整增量矩阵。LoRA 原论文提出用这类低秩更新适配预训练模型。[LoRA 原论文](https://arxiv.org/abs/2106.09685)

一层完整更新需要 d_out×d_in 个参数，LoRA 需要 r×(d_in+d_out)。若两边都是 4096，完整矩阵有 16,777,216 个参数；r=8 时，适配器只有 65,536 个，约为原矩阵的 0.39%。若 32 层各对两个这样的投影加适配器，总数为 4,194,304。

这是参数化约束：增量秩最多为 r，但模型原有 W 并不因此变成低秩。它也不保证 r 越大越好。rank、目标层、学习率、训练数据与缩放方式共同决定效果。固定 alpha 而增加 r，会同时改变原始公式的缩放，比较实验时应记录这些耦合关系。

## 初始化解释了一个看似奇怪的梯度现象

常见初始化让 A 非零、B 为零，于是初始增量 BA 为零，模型起点与底座一致。此时第一次反向传播中，A 的梯度可能为零，因为它前面乘着零矩阵 B；B 通常可以得到非零梯度。一次更新后，A 才逐渐获得学习信号。这不是适配器一定接错了。

不同初始化方案与 rank-stabilized LoRA 会改变细节。PEFT 文档明确区分初始化、缩放、目标模块和额外保存模块，因此看到配置项时要读它在当前版本中的具体含义。[PEFT LoRA 文档](https://huggingface.co/docs/peft/v0.21.0/package_reference/lora)

目标层名称也取决于模型架构。有的使用独立 q、k、v 投影，有的使用融合矩阵；某个教程中的 `q_proj` 不一定出现在另一个模型里。应列出匹配到的层、可训练参数名和总数，而不只相信“已注入 LoRA”的日志。

## QLoRA 再压缩冻结底座

普通 LoRA 可以把底座保存在 BF16 或 FP16，仍需要约每参数 2 字节。QLoRA 的核心组合是在低位量化底座上训练适配器；原论文讨论 NF4、双重量化和分页优化器等设计。[QLoRA 原论文](https://arxiv.org/abs/2305.14314)

量化权重的存储格式与矩阵运算的数据类型不是同一件事。底座可以以 4 bit 存储，在运算中通过量化内核使用更高精度计算；适配器与某些未量化模块也可能采用不同 dtype。不能据“4 bit”推断所有激活、梯度和优化器状态都只有四位。

以理想化的 70 亿参数底座为例，BF16 权重约为 140 亿字节，即 13.04 GiB；纯 4 bit 数据约为 35 亿字节，即 3.26 GiB。实际还要加量化尺度、元数据、未量化层和工作空间，所以 3.26 GiB 只是存储下界式估算，不是训练显存承诺。

在 bitsandbytes 集成中，量化类型、计算 dtype 和嵌套量化是不同配置。官方文档还区分训练与推理的设备放置用法；不要把推理示例中的自动分配策略无条件用于训练。[Transformers bitsandbytes](https://huggingface.co/docs/transformers/quantization/bitsandbytes)

## 写一张自己的显存账本

可以把总峰值近似拆成：冻结底座、可训练参数、梯度、优化器状态、激活和临时缓冲。前几项更容易静态估算，后两项对序列长度、微批次、注意力内核和 checkpoint 策略十分敏感。

```python
layers, targets = 32, 2
width, rank = 4096, 8
adapter_params = layers * targets * rank * (width + width)
gib = 1024 ** 3
print("adapter params:", adapter_params)
print("7B BF16 weight GiB:", 7_000_000_000 * 2 / gib)
print("7B raw 4bit GiB:", 7_000_000_000 * 0.5 / gib)
# 教学假设：适配器参数、梯度和状态合计每参数 16 字节。
print("adapter state MiB:", adapter_params * 16 / 1024 ** 2)
```

最后一个数在该假设下为 64 MiB，但不能据此得出“训练额外开销只有 64 MiB”。梯度必须通过网络传播，激活仍可能很大。增加目标模块也会增加适配器参数与相关计算；词表层、bias 或 `modules_to_save` 若被设为可训练，账本还需补上它们。

当显存主要消耗在长序列激活上，把 rank 从 16 降到 8 的帮助可能小于减小序列长度或微批次。反之，权重放不下时，单纯增加梯度累积步数不能减少底座权重大小。先识别最大项，再选择对应方法。

## 冻结权重不等于关闭整层自动微分

考虑线性映射 `y=Wx`。即使 W 不需要梯度，只要更早层中的适配器需要更新，仍然需要计算损失对 x 的导数，其中会用到 W 的转置。冻结参数通常通过 `requires_grad=False` 表达；把整个底座前向放入 `no_grad()`，则可能切断通向较早适配器的路径。

这个差别也解释了 LoRA 为什么不能消除所有反向计算。它避免的是对大量底座参数形成梯度与维护优化器状态，而不是让模型其余部分从训练图中消失。具体实现可以利用冻结结构做优化，但学习者不应据“底座不更新”自行省略输入梯度。

从效果评估看，底座是否适合任务也仍然重要。一个小 rank 适配器能重新组合已有表示，但并不保证可以在很少数据下补齐所有欠缺能力。比较两个 rank 时，最好使用相同数据顺序、步数与生成协议，同时记录参数量和训练时间；若只有训练 loss 下降，仍不足以判断额外容量值得保留。

## 保存适配器与合并权重是两种交付

适配器文件通常需要匹配的底座、模型 revision、tokenizer 与配置才能恢复完整行为。只保留一个很小的权重文件并不等于保留了全部实验条件。合并则把增量写入底座权重，可能改变存储大小、精度和部署方式。

对量化底座，合并与再次量化还可能引入额外误差或临时显存峰值。应先在固定提示集上对比合并前后行为，再决定是否交付合并版本。不能把“数学上可以相加”直接替换成“所有实现都能无损、原地、低显存合并”。

## 个人主机实验与验收

先只运行参数计算器，把 rank 从 4 改到 8、16，验证适配器参数量线性增长。再用 CPU 上的 8×8 小矩阵构造 `W+sBA`，比较直接合并后的线性输出与两条分支输出，允许浮点容差。令 B 全零，确认初始输出等于底座；进行一次反向，观察 A、B 梯度的差别。

若之后在已配置的 GPU 上训练，先从短序列与微批次 1 开始，记录加载后、前向后、反向后和第一次 optimizer step 后的显存。本文没有执行该 GPU 实验，也不声称某张卡能训练某个规模。

验收是能列出真实可训练层，手算参数量与程序统计一致，说明量化存储和计算精度的区别，并完成适配器保存与重新加载核对。LoRA 和 QLoRA 的价值在于改变账本中的特定项，理解这些项比记住一条“最低显存配置”更可靠。
