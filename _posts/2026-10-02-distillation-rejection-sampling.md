## 先分清被转移的是什么

蒸馏可以让学生拟合教师的概率分布，也可以让学生学习教师生成的完整文本。前者通常需要 logits 或概率，后者只需要输出序列。两种数据携带的信息不同，因此“有教师答案”并不等于做了经典软标签蒸馏。

[经典知识蒸馏论文](https://arxiv.org/abs/1503.02531)强调软目标提供的类别关系。例如教师对三个选项给出 (0.7,0.2,0.1)，除了最可能的 A，还表达了 B 比 C 更合理。若只留下硬标签 A，这一相对信息就消失了。

语言模型场景下，完整输出又包含风格、格式、步骤和长度等信息。学生可能学到任务能力，也可能学到教师的口头禅和错误。蒸馏是压缩一种行为分布，不是保证把教师全部能力无损迁移。

## 概率蒸馏与温度

设教师 logits 为 z_T，学生为 z_S，温度为 τ，软分布为 softmax(z/τ)。常见软目标损失可以写成：

$$
\mathcal L_{\mathrm{soft}}
=\tau^2 D_{\mathrm{KL}}\left(
p_T^\tau\Vert p_S^\tau
\right).
$$

教师固定时，最小化该 KL 与最小化教师分布下的交叉熵，对学生具有相同梯度。τ 增大会软化分布，使低概率类别的信息更明显；τ² 是经典设置中用于调节梯度尺度的因子，不应在换成另一种损失或参数化后机械照搬。

自回归蒸馏还要问：在哪些前缀上匹配分布？教师生成的前缀、学生生成的前缀和真实数据前缀不同。学生部署时会访问自身错误造成的新状态，只在教师完美轨迹上训练可能出现分布偏移。单纯增加每条教师轨迹的重复次数无法解决这个覆盖问题。

## 序列蒸馏的目标更接近 SFT

只拿到教师回答 y 时，可以最小化：

$$
\mathcal L_{\mathrm{seq}}
=-\sum_t\log\pi_S(y_t\mid x,y_{<t}).
$$

这里的训练目标与监督微调形式相同，区别主要在数据来源。若教师输出了一段解释与最终答案，学生会拟合这段可见文本；它不意味着学生复制了教师不可见的内部机制。

“答案正确”也不能自动证明解释可靠。可能存在先猜对答案、再生成不成立解释的样本。因此若训练目标包括可审计推导，应增加对解释质量的检查，不能只用最终数字过滤后把所有中间文本视为金标准。

[STaR](https://arxiv.org/abs/2203.14465)展示了生成推理、筛选和迭代训练的路径，同时包含其特定的数据构造步骤。引用它时应说明采用了哪些步骤，而不是把任意自生成数据训练都称作完整复现。

## 筛选如何改变训练分布

教师生成分布为 q(y∣x)，接受函数为 a(x,y)，取值在 0 到 1。被接受样本的分布为：

$$
q_{\mathrm{accepted}}(y\mid x)
=\frac{q(y\mid x)a(x,y)}
{\sum_{y'}q(y'\mid x)a(x,y')}.
$$

假设 q=(0.7,0.2,0.1)，筛选器接受 A、B，拒绝 C，则学生看到的分布为 (7/9,2/9,0)。它学习的是筛选后的教师，而不是原教师。若 C 是少见但正确的解法，筛选规则就会减少多样性；若 C 是错误答案，这种变化可能正是希望得到的结果。

工程中常说的“拒绝采样微调”经常指先生成再按质量过滤。它与概率论中为精确采样目标分布而设计接受率的经典拒绝采样，需要作出区分。随意用一个质量阈值过滤，并不会自动产生某个预先指定的数学目标分布。

## Best-of-N 与保留所有通过样本不同

每题生成 N 个回答，只选择分数最高的一个，是 best-of-N。把所有通过阈值的回答都保留，则会给容易题更多训练样本。如果每题只保留一个，就控制了题目权重，却可能丢掉多种正确解法。

当单次独立生成通过率为 p 时，N 次至少有一次通过的概率是 1−(1−p)^N。p=0.2、N=8 时，该概率约为 0.832；但“至少找到一次”的提升来自八次采样预算，不应误报为单次生成准确率。

同样，在独立且通过率固定的理想条件下，获得一个通过样本平均需要 1/p 次尝试。困难题通过率低，会消耗更高预算。真实生成通常相关、长度不同，因此记录实际 token 成本比只记录候选数量更可靠。

## 一个无需模型的采样模拟

```python
import random
from collections import Counter

rng = random.Random(7)
labels = ["A", "B", "C"]
counts = Counter()
attempts = 20000
for _ in range(attempts):
    answer = rng.choices(labels, weights=[0.7, 0.2, 0.1])[0]
    if answer != "C":
        counts[answer] += 1

accepted = sum(counts.values())
print("acceptance", accepted/attempts)
print({k: counts[k]/accepted for k in labels})
```

预期接受率接近 0.9，接受后的 A、B 比例接近 7/9 与 2/9；有限样本会偏离解析值。验收时记录种子、尝试数和误差，重复多个种子查看稳定性。

第二轮把接受规则改为只保留 A，观察分布如何坍缩；第三轮让 B 以 0.5 概率接受，计算新的解析分布并对照模拟。再用频数最大似然拟合一个三类学生，就能看到“学生接近筛选数据”与“学生接近原教师”是两种不同评价。

## 数据质量比复制次数更重要

至少保存原始提示、教师版本、生成参数、所有候选、筛选器版本、分数和最终接受原因。只保存赢家会让后续无法判断筛选器错杀了什么，也难以计算真实生成成本。

训练测试划分必须发生在生成之前。相同原题改写后进入测试集，仍可能造成污染。对于模板任务，按模板或推理结构切分，通常比随机行切分更能检验泛化。若教师看到了测试答案或生成提示中含有答案提示，相关数据也不能进入独立评测。

[ReST](https://arxiv.org/abs/2308.08998)研究了生成、筛选与改进的迭代流程；它的具体结论与任务设置相关。迭代时还要保留初始模型和上一轮模型作为基线，否则某个筛选器盲点可能被一轮轮放大。

## 个人主机上的验收闭环

构造三个难度层级的合成分类题，教师是已知概率表，验证器可控地引入少量误判。比较不筛选、阈值筛选和 best-of-N 三种数据构造方式，训练一个表格学生，分别记录单次正确率、覆盖率、分布 KL 与每个有效样本的尝试成本。

合格的结论应说明预算是否相同、每题权重是否相同、测试题是否独立，以及筛选误判如何影响学生。若只展示筛选后的数据正确率提高，却没有学生在新题上的评价，就只能证明筛选器改变了样本，尚未证明蒸馏改善了泛化。
