## “对齐”至少有两种不同含义

多模态系统首先要让视觉信息能够进入语言模型：图像经过编码器，得到一组特征，再通过投影层、查询模块或其他连接结构形成语言模型可使用的表示。这是表示层面的对接。

后训练还希望模型根据这些信息遵循指令、减少幻觉、完成问答或工具任务。这是行为层面的学习。连接器成功传递了图像特征，不等于模型已经学会拒绝编造；偏好优化让语言更礼貌，也不等于视觉识别更准确。

[BLIP-2](https://arxiv.org/abs/2301.12597)展示了一种连接冻结视觉编码器和语言模型的设计；[Visual Instruction Tuning](https://arxiv.org/abs/2304.08485)展示了视觉指令数据对交互行为训练的作用。两者是具体架构与训练方案，不应被概括成所有多模态模型必须遵循的固定两阶段配方。

## 输入流水线决定模型实际看到什么

原图可能先缩放、裁剪、切块或补边，然后转成特征。细小文字、表格线、坐标标签和远处物体可能在这一步丢失。若训练用高分辨率多切块，评测却只给缩小图，模型看到的信息已经不同，不能把全部性能变化归因于后训练算法。

样本应保存图像标识与内容哈希、预处理配置、裁剪或切块信息、文本对话、答案、来源和许可范围。同一张图的不同分辨率、不同裁剪与改写问题，要按原始图像分组划分数据，避免训练集和测试集共享视觉内容。

视频还要记录帧采样时刻与顺序，音频要记录采样率、切片边界和转写对齐。把“输入文件路径”当成完整数据定义，会漏掉模型实际消费的关键变换。

## 训练目标依然需要精确 mask

在给定图像 v 和提示 x 时，文本答案 y 的监督损失可以写为：

$$
\mathcal L_{\mathrm{SFT}}
=-\sum_{t\in\mathcal M}
\log p_\theta(y_t\mid v,x,y_{<t}),
$$

集合 M 指定被监督的答案 token。图像占位符、视觉特征位置、prompt、padding 和工具观察是否参与某项损失，必须与架构及目标一致。不能把单模态的 labels 处理代码直接复制后假设所有位置仍有相同语义。

冻结视觉编码器、只训练连接器通常减少可训练参数，但不代表训练成本只取决于连接器大小。视觉特征仍需生成，语言部分可能仍需反向传播激活。若提前缓存特征，则节省重复编码，但数据增强和预处理变化会要求重新生成缓存。

偏好训练也应保持比较条件一致：同一张图、同一问题下，比较两个回答。若赢家看到高分辨率图、输家只看到模糊缩略图，偏好标签混入了输入条件差异，无法单独解释成回答质量差异。

## 模型可能靠文字先验“猜对”

问题“这张厨房照片里有没有冰箱”，即使看不到图，模型也能利用常识猜“有”。如果数据中厨房几乎总有冰箱，平均准确率很高，却不能证明模型认真使用了图像。

一个更有辨别力的测试是构造匹配的反事实对：问题文本相同，一张图有目标物体，另一张图没有。模型应随视觉证据改变答案。还可做图像交换、图像遮挡和问题重写，检查表现究竟依赖哪个模态。

[POPE](https://arxiv.org/abs/2305.10355)研究对象幻觉的评估方式。它提示我们不能只看回答是否流畅，还要检查提到的物体是否有视觉证据。不过对象存在性只覆盖多模态能力的一部分，不等于 OCR、空间推理、图表理解和跨学科问题都已测完。

## 三类错误需要分开处理

感知错误是没有读对输入，例如把图表坐标 10 看成 70；推理错误是输入已读对，却执行了错误计算；表达错误是结论正确但未按要求输出单位或结构。

同一个最终错误，可能需要不同训练改动。感知错误可能与分辨率、视觉编码器或 OCR 数据有关；推理错误可能需要更好的任务示范或可验证监督；表达错误可能通过少量格式数据改善。只收集“这个回答不好”的二元偏好，往往不足以定位问题。

评测时可以要求可验证的中间产物，例如先提取表格数字，再算总和，但这些中间文本不应自动被视作模型内部机制。它们只是额外可观察的任务输出，仍需独立检查。

## 一个 CPU 上可做的反事实实验

不下载视觉模型，也能用合成特征演示数据捷径。把“图像”简化为亮度特征 image_signal，标签由它决定；把文本线索 cue 设为训练时高度相关、测试时反转。

```python
examples = [
    {"image_signal": 1, "cue": 1, "label": 1},
    {"image_signal": 0, "cue": 0, "label": 0},
]
counterfactual = [
    {"image_signal": 1, "cue": 0, "label": 1},
    {"image_signal": 0, "cue": 1, "label": 0},
]

def accuracy(data, feature):
    return sum(x[feature] == x["label"] for x in data) / len(data)

for feature in ["cue", "image_signal"]:
    print(feature, accuracy(examples, feature),
          accuracy(counterfactual, feature))
```

两个规则在原始样本都完全正确；在反事实集合里，依赖文本 cue 的规则完全失败，依赖图像特征的规则仍然正确。这是设计好的解析结果，证明“普通测试无法区分两种策略”的可能性，并非真实视觉模型实验。

扩展实验时，可生成二维小方格，标签由亮格位置决定，文本线索加入可控噪声，再训练一个线性分类器。比较只用文本、只用图像特征和两者结合，分别报告原分布与反事实集准确率。普通 CPU 足以完成这个代理任务，但它不能证明完整视觉语言模型具有同样行为。

## 评测矩阵比单一总分更有用

至少把任务分成对象识别、计数、OCR、空间关系、图表和领域知识，并按分辨率、图像质量与回答长度分组。对拒答也要区分证据不足与无必要拒绝；只惩罚幻觉而不检查可回答题，可能得到一个什么都不敢回答的系统。

对于开放回答，可以组合结构化答案匹配、人工抽检和独立评审模型，但应报告评审者的输入条件与规则。只给评审者文本而不给图像，通常无法验证回答是否真的符合图像。

[MMMU](https://arxiv.org/abs/2311.16502)提供了多学科、多模态理解与推理的评测视角。它不替代具体业务的领域测试，也不应在训练数据污染未排查时被当作可靠泛化证据。

## 个人主机实验的验收标准

保留生成脚本、种子、原始样本和分组切分规则；确保同一底图的变体不跨训练测试；展示文字线索反转前后的指标；人工检查至少十对视觉反事实；分别统计感知、推理和输出格式错误。

若更换图像预处理，重新记录特征缓存版本并复跑评测。若只修改文本模板，也应检查输入占位符与答案 mask。完成这些小实验后，再扩大模型与数据规模，才能把性能变化归因到可解释的训练设计，而不是被看不见的数据捷径带着走。
